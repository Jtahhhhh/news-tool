JPEG/PNG và hạn chế lease/hủy render; xem audit trước khi vận hành video.

Pipeline local: lấy tin → chọn tin → duyệt kịch bản → tạo audio → dựng và duyệt
video dọc. Video uses VieNeu-TTS and FFmpeg locally; the application does not
automatically post to TikTok. The optional TikTok Upload module transfers a
reviewed video after separate user consent; the user completes posting in TikTok.

## Start

```bash
cp .env.example .env
docker compose up --build
```

Open `http://localhost:${WEB_PORT:-8000}`. PostgreSQL, TTS, and workers are only
reachable inside the Compose network. Named volumes retain database data, model
weights, uploaded assets, audio cache, and rendered videos across container
recreation. The web container runs Alembic before serving requests.

The first TTS start downloads model weights into `tts_models` and can take
several minutes. The initial profile uses CPU, fp32, one TTS stream, and one
render worker. Do not raise concurrency until the measurements below are
recorded.

## Video workflow

1. Approve a structurally valid script generated by a real provider.
2. Open **Video**, optionally upload an image/MP4, then choose the asset and crop
   for every scene. If there is no asset, the renderer uses a text template.
3. Add pronunciation replacements for names, numbers, or abbreviations. Use
   **Chỉ tạo audio để nghe thử** to listen to every scene before rendering, then
   start the render with the same settings. The page polls the durable job; no
   TTS or FFmpeg work runs in the web request.
4. Open the created version, listen to each scene, watch the MP4, then approve
   or reject that exact file. A re-render produces a new unapproved version and
   reuses cached audio when narration and voice are unchanged.

Changing narration is rejected at the video boundary. Edit and approve a new
script version first. Videos and assets marked **TEST** retain that marker and
must not enter a future publishing flow. The pipeline never shortens narration;
it warns when measured audio exceeds the script target.

## Recovery and diagnosis

Jobs move through `queued → generating_audio → rendering → succeeded/failed/
cancelled`. Audio completion is committed as a checkpoint. On restart, the
worker checks existing output and requeues expired work; content hashes and a
partial unique index prevent duplicate audio, versions, and simultaneous jobs.

```bash
docker compose ps
docker compose logs --tail=200 render-worker tts
docker compose exec render-worker ffprobe -v error -show_streams /data/video/<file>.mp4
docker stats --no-stream
```

For an initial benchmark, record peak RAM from `docker stats`, job elapsed time,
audio duration, video duration, and output size for the two-scene test and one
real approved story. Review number reading (`120`), names, a long sentence, and
mixed Vietnamese/English before accepting a voice/model change.

The bundled upstream is VieNeu-TTS v3 Turbo. Its source and voice/model license
must be reviewed again before redistribution or commercial packaging; this
repository records the upstream source in `vendor/VieNeu-TTS` rather than
silently substituting an older model.

## Verification

```bash
docker compose config --quiet
docker compose build
docker compose run --rm web pytest -q
```

The test suite uses only the separate database whose name ends in `_test`.


## Groq / GPT-OSS-120B

Xem [hướng dẫn cấu hình và thêm key Groq](docs/HUONG-DAN-GROQ.md), [audit LLM](docs/AUDIT-LLM-GROQ.md) và [kết quả kiểm thử](docs/GROQ-VALIDATION.md).

Đặt `LLM_PROVIDER=groq`, `GROQ_MODEL=openai/gpt-oss-120b`, key trong `.env.credentials`; dùng `env:GROQ_API_KEY` trên giao diện. Policy đã lưu cần cập nhật tại `/llm`. Worker LLM tách khỏi crawl, nguồn được cố định, đầu ra kiểm tra grounding và chỉ repair một lần.
